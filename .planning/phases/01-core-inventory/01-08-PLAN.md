<objective>
Fix the edit drawer pre-fill bug where React Hook Form's `defaultValues` are set from `undefined` (before `useLiveQuery` resolves) causing the form to render with empty fields.

Purpose: When a user taps Edit on a wine detail page, the drawer must open with all existing values pre-filled. Currently the form initializes before Dexie resolves, locking in empty defaults.

Root cause (from UAT diagnosis):

1. `WineDrawer` passes `editingWine ?? undefined` to `WineForm` before `useLiveQuery` resolves — form initializes with `undefined` → empty defaults
2. `WineForm` has no `useEffect + form.reset()` to re-initialize when `defaultValues` later becomes a real wine object
3. `type` and `format` Select components use `defaultValue={field.value}` (uncontrolled) instead of `value={field.value}` (controlled) — even if `reset()` were called, they wouldn't update

Output: Edit drawer opens with all fields pre-filled correctly.
</objective>

**Fix A — WineDrawer.tsx: Gate WineForm mount until editingWine resolves**

The problem: When `editingWineId` is set, `useLiveQuery` starts as `undefined` (loading). We immediately pass `editingWine ?? undefined` to `WineForm`, which initializes with empty defaults. By the time `useLiveQuery` resolves to the real wine, the form's `defaultValues` have already been locked in.

Fix: In edit mode, do NOT render `<WineForm>` until `editingWine` has resolved from `undefined` to either a `LocalWine` object or `null`/`undefined` (wine not found). Show a loading state instead.

```tsx
// In WineDrawer, replace the current <WineForm> render:

const isLoading = isEdit && editingWine === undefined;

// In JSX:
<div className="px-4 pb-8 overflow-y-auto">
  {isLoading ? (
    <div className="flex items-center justify-center py-12 text-white/40">
      Loading…
    </div>
  ) : (
    <WineForm
      defaultValues={editingWine ?? undefined}
      onSubmit={handleSubmit}
      onCancel={closeDrawer}
      isEdit={isEdit}
    />
  )}
</div>;
```

This ensures WineForm only mounts (and calls `useForm`) after `defaultValues` is a real value, not `undefined`.

---

**Fix B — WineForm.tsx: Two sub-fixes**

**B1 — Add `useEffect + form.reset()` for async defaultValues:**

Even with the WineDrawer gate, add defensive `form.reset()` in WineForm for robustness (and to handle any future case where defaultValues arrives late):

```tsx
import { useEffect } from "react"; // add to existing react import

// After useForm() call, add:
useEffect(() => {
  if (defaultValues) {
    form.reset({
      name: defaultValues.name ?? "",
      producer: defaultValues.producer ?? "",
      vintage: defaultValues.vintage ?? null,
      type: defaultValues.type ?? "red",
      varietal: defaultValues.varietal ?? null,
      region: defaultValues.region ?? null,
      appellation: defaultValues.appellation ?? null,
      country: defaultValues.country ?? null,
      quantity: defaultValues.quantity ?? 1,
      format: defaultValues.format ?? "750ml",
      storageLocation: defaultValues.storageLocation ?? null,
      purchasePrice: defaultValues.purchasePrice ?? null,
      purchaseDate: defaultValues.purchaseDate ?? null,
      purchaseSource: defaultValues.purchaseSource ?? null,
      drinkFrom: defaultValues.drinkFrom ?? null,
      drinkBy: defaultValues.drinkBy ?? null,
      notes: defaultValues.notes ?? null,
    });
  }
}, [defaultValues]); // eslint-disable-line react-hooks/exhaustive-deps
```

**B2 — Fix `type` and `format` Select from uncontrolled to controlled:**

Current code uses `defaultValue={field.value}` on both Select components — this is set once on mount and never updates when `form.reset()` is called.

Change both Select components to use `value={field.value}` instead of `defaultValue={field.value}`:

For the **type** Select (around line 134):

```tsx
// BEFORE:
<Select onValueChange={field.onChange} defaultValue={field.value}>
// AFTER:
<Select onValueChange={field.onChange} value={field.value}>
```

For the **format** Select (around line 215):

```tsx
// BEFORE:

// AFTER:

```

**B3 — Auto-expand optional section when editing a wine with optional fields:**

When editing, the optional fields section should be pre-expanded if the wine has any optional fields set (so the user can see and edit them):

```tsx
// Change the useState initialization:
// BEFORE:
const [showOptional, setShowOptional] = useState(false);
// AFTER:
const [showOptional, setShowOptional] = useState(() => {

    defaultValues.varietal ||
    defaultValues.appellation ||
    defaultValues.storageLocation ||
    defaultValues.purchasePrice ||
    defaultValues.purchaseDate ||
    defaultValues.purchaseSource ||

```
